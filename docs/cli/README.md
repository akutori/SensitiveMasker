# masker CLIコマンド一覧

| コマンド | 一言で言うと |
|---|---|
| [`masker init`](#masker-init) | 初回セットアップ(鍵+DB作成) |
| [`masker mask`](#masker-mask) | テキストをマスキングする(本体機能) |
| [`masker profile list`](#masker-profile-list) | プロファイル一覧を見る |
| [`masker profile use`](#masker-profile-use) | アクティブプロファイルを切り替える |
| [`masker profile create`](#masker-profile-create) | 新規プロファイルを作る |
| [`masker profile delete`](#masker-profile-delete) | プロファイルを削除する |
| [`masker export`](#masker-export) | プロファイルを暗号化して書き出す |
| [`masker import`](#masker-import) | エクスポートしたファイルを取り込む |

## masker init

**何をするか**: 鍵ファイルとデータベースを初期化する。

初回実行時のみ実際に初期化し、既に初期化済みの場合は何もしない。
何度実行しても安全。

`mask`・`profile`系のコマンドは、これが完了していないと使えない。

## masker mask

**何をするか**: テキストをマスキングする(このCLIの本体機能)。

```bash
cat file.log | masker mask
```

`--profile <name>`で使うプロファイルを指定できる(省略時はアクティブプロファイル)。

入出力の指定方法によって4つの動作モードがある(組み合わせ不可)。

| モード | 指定方法 | 用途 |
|---|---|---|
| 標準入出力 | 何も指定しない | `cat file.log \| masker mask` のような単発のパイプ処理 |
| ファイル | `--input <file> --output <file>` | 1つのファイルをまとめてマスキング |
| バッチ | `--batch --input <dir> --output <dir>` | ディレクトリ内の全ファイルを一括処理 |
| ストリーム | `--stream` | `tail -f`など終了しないコマンドの出力をパイプし、都度マスクして即座に出力する |

<details>
<summary>詳細・注意点</summary>

**バッチモード**

- `--input`と`--output`に同じディレクトリは指定できない(元データが上書きされ復元できなくなるため)
- サブディレクトリ・シンボリックリンクは対象外(スキップ件数のみ標準エラー出力に表示)
- 1ファイルの書き込みが失敗すると、それ以前に処理済みのファイルは残したまま停止する(やり直し・巻き戻しはしない)
- 既定では全ファイルで同じ対応表(マッピング)を共有する(同じ値は同じダミー値になる)。`--reset-mapping-per-file`でファイルごとにリセットできる

**出力先の制限**

- `--output`(ファイル・バッチ共通)にアプリのデータフォルダ(暗号化DB・鍵ファイルの保存先)自身やその内側は指定できない(`profiles.db`等の誤上書き防止)

**文字エンコーディング**

- 既定はUTF-8前提。UTF-8として解釈できないバイト列があっても停止せず、置き換えて処理を続行する(警告は標準エラー出力に表示。`--stream`では最初の1回のみ)
- この置き換えにより、機微情報の値の内部にちょうど不正なバイト列が入っていた場合、その値はマスクされないことがある(警告は出る)
- 非UTF-8(Shift-JIS等)の入力は`--encoding <label>`で明示的に指定する([WHATWGラベル名](https://encoding.spec.whatwg.org/#names-and-labels)、例: `shift-jis`)。自動検出はしない

**ストリームモードのメモリ**

- 対応表と1行分のバッファをプロセス終了まで保持し続ける。長時間・大量のユニークな値が出続ける運用ではメモリ使用量が増えていく

</details>

## masker profile list

**何をするか**: 登録済みプロファイルの一覧を表示する。

プロファイル名・ルール数・アクティブ/お気に入りの状態・更新日時を表示する。

## masker profile use

**使い方**: `masker profile use <name>`

アクティブプロファイルを切り替える。
以後`--profile`を省略した`mask`はこのプロファイルを使う。

## masker profile create

**使い方**: `masker profile create <name> [--from-json <file>]`

新規プロファイルを作成する。
`--from-json`を省略すると、ルール0件の空プロファイルになる。

<details>
<summary>--from-jsonの詳細</summary>

指定したファイル(ルール定義のJSON配列)を読み込み、初期ルール入りで作成する。

以下のいずれかに該当する場合はエラーになり、プロファイルは作成されない(部分的な作成はしない)。

- ファイルが存在しない、または読み込めない
- JSONとして構文が不正
- 個々のルール定義が不正(正規表現が不正、`fixed`モードで`fixed_value`未指定など)
- ルール名がファイル内で重複している

JSON形式(1要素が1ルール):

```json
[
  {
    "name": "ip",
    "pattern_type": "regex",
    "pattern": "\\d+\\.\\d+\\.\\d+\\.\\d+",
    "mode": "sequential",
    "prefix": "__MASK_IP_"
  }
]
```

- `pattern_type`: `"literal"` または `"regex"`
- `mode`: `"fixed"`(常に同じ値に置換。`fixed_value`が必須) または `"sequential"`(検出順に連番。`prefix`が必須)
- `enabled`: 省略可(既定`true`)
- `description`: 省略可

プロファイル名は空文字列・前後の空白も特別扱いされず、そのまま名前にできる。

</details>

## masker profile delete

**使い方**: `masker profile delete <name>`

プロファイルを削除する。
アクティブなプロファイルは削除できない(先に`profile use`で切り替える)。

## masker export

**使い方**: `masker export [--profile <name>] --output <file>`

プロファイルをパスフレーズで暗号化し、ファイルへ書き出す(他のマシン・他のユーザーへの持ち出し用)。

- `--profile <name>`: そのプロファイル1件のみエクスポート
- 省略時: 全プロファイル+アクティブプロファイル名をまとめてエクスポート(PC移行用)

パスフレーズは実行時にTTYへ直接入力する(引数・環境変数・標準入力からは渡せない。シェル履歴に残さないため)。

<details>
<summary>詳細・注意点</summary>

- `--output`にアプリのデータフォルダ自身やその内側は指定できない(`profiles.db`等の誤上書き防止)
- パスフレーズは2回入力(タイプミス対策)。不一致なら何も書き出さずエラー
- 空のパスフレーズは保護にならないため拒否される
- 強度チェック(`zxcvbn`)でスコア3未満(0〜4の5段階)の場合は警告し、続行確認する(強制はしない。yと答えれば弱いままエクスポート可能)
- 出力ファイルは[age](https://age-encryption.org/)形式のバイナリ(scrypt+ChaCha20-Poly1305)。拡張子は任意

</details>

## masker import

**使い方**: `masker import --input <file> [--yes]`

`masker export`で作成したファイルからプロファイルを取り込む。
単一/全体はファイルの中身から自動判別する(`--profile`相当の引数は無い)。

パスフレーズはexportと同様、TTY入力のみ。
貼り付けなどで前後に空白(改行・タブ・全角スペース等)や、ゼロ幅文字(U+200B・U+200C・U+200D・U+2060)・BOM(U+FEFF)が混ざっていても復号できるよう、入力のまま復号に失敗したときだけ、それらを除いたものでもう一度試す(前後に空白を含むパスフレーズで作ったファイルは、入力のままで復号できる。空白を足した入力は試さない)。

<details>
<summary>復号・検証に失敗する場合</summary>

以下のいずれかが原因で、プロファイルは作成されない。

- パスフレーズが誤っている、またはファイルが破損している
- 鍵ファイル(GUIのエクスポートで「鍵ファイル」を選んだ場合)で暗号化されたファイルである(専用のメッセージが出る。CLIは、鍵ファイル方式を扱わないため、GUIの「インポート」で、鍵ファイルを指定する)
- エクスポート元のマシンが著しく高速で、暗号化のワークファクタがこのマシンの許容上限(2^22)を超えている(専用メッセージが出る。パスフレーズ再入力では解決しない)
- 正しく復号できたが、`masker export`のデータでない、または対応していないフォーマットバージョン
- (全体のみ)ファイル内に同名プロファイルが複数含まれている(手動編集等。正規のエクスポートでは起きない)

</details>

<details>
<summary>取り込み後の挙動</summary>

**単一プロファイル**: 同名が既に存在する場合はエラー(作成されない。リネームしない)。

**全体(全プロファイル+設定)**:

- 名前が重複するプロファイルは自動的にリネームされる(例: `SIP監視用` → `SIP監視用 (インポート)`。以降は`(インポート 2)`のように連番)
- 参照するタグが無ければ新規作成する
- 書き込み前に一覧を表示し、「続行しますか? (y/N)」を1回確認してから全件をまとめて書き込む(一部だけ作成されることはない)
- `--yes`で確認を省略できる(cron/SSH等の非対話環境向け)。`--yes`無しで標準入力がTTYでない場合は即座にエラー
- アクティブプロファイル名は、取り込み先に既にアクティブが設定されている場合は適用されない(未設定の場合のみ採用。リネームされていればリネーム後の名前を採用)

</details>
