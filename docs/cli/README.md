# masker CLIコマンド一覧

## masker init

鍵ファイルとデータベースを初期化する。初回実行時のみ実際に初期化し、既に初期化済みの場合は何もせず終了する(何度実行しても安全)。

`mask`や`profile`系のコマンドは、初期化が完了していないと実行できない。

## masker mask

テキストをマスキングする。`--profile <name>`でプロファイルを指定できる(省略時はアクティブプロファイルを使用)。

入出力の指定方法によって4つの動作モードがある(これらは組み合わせられない)。

| モード | 指定方法 | 用途 |
|---|---|---|
| 標準入出力(一括) | 何も指定しない | `cat file.log \| masker mask` のような単発のパイプ処理 |
| ファイル | `--input <file> --output <file>` | 1つのファイルをまとめてマスキング |
| バッチ | `--batch --input <dir> --output <dir> [--reset-mapping-per-file]` | ディレクトリ内の全ファイル(サブディレクトリは対象外)を一括処理 |
| ストリーム | `--stream` | 標準入力を1行ずつ受け取り、都度マスキングして即座に出力する。`tail -f`など終了しないコマンドの出力をパイプする用途向け |

バッチモードの`--reset-mapping-per-file`について: 既定ではバッチ内の全ファイルで同じ値の対応表(マッピング)を共有する(同じ電話番号が複数ファイルに出てきても同じダミー値になる)。このオプションを付けるとファイルごとにマッピングをリセットする(ファイル間で対応関係を持たせたくない場合に使う)。

バッチモードの`--input`と`--output`に同じディレクトリを指定することはできない(元データがマスク後の内容で上書きされ復元できなくなるため、実行前にエラーで停止する)。また、入力ディレクトリ内のサブディレクトリ・シンボリックリンクは対象外(再帰もリンクの追跡もしない)で、スキップした件数のみ標準エラー出力に表示する。バッチ処理中に1ファイルの書き込みが失敗した場合、それ以前に処理済みのファイルの出力は残ったまま停止する(バッチ全体としてのやり直し・巻き戻しは行わない)。

いずれのモードも入力は必ずしもUTF-8とは限らないログ・コンソール出力を想定している。既定(`--encoding`未指定)ではUTF-8として解釈し、UTF-8として解釈できないバイト列があってもエラーで停止せず、該当部分を置き換えて処理を継続する。置き換えが発生した場合は標準エラー出力に警告を表示する(`--stream`は入力全体で最初の1回のみ)。この置き換えにより、機微情報の値の内部にちょうど不正なバイト列が入り込んでいた場合、その値は本来のパターンと一致しなくなりマスクされないことがある(警告は出るが、値そのものは無警告で漏れるわけではない)。

入力がUTF-8以外のエンコーディング(Shift-JIS等)で書かれている場合は`--encoding <label>`で明示的に指定する。指定したエンコーディングとして正しくデコードしてからマスク処理するため、全角文字を含むパターンもそのエンコーディングとして書かれている限り正しく検出できる。`label`は[WHATWG Encoding Standard](https://encoding.spec.whatwg.org/#names-and-labels)のラベル名(例: `shift-jis`、`euc-jp`、`utf-8`)。自動検出は行わないため、入力の実際のエンコーディングが分からない場合は指定しない(既定のUTF-8前提のまま処理される)。`--encoding`を指定しない限り、この機能によって既定の動作が変わることはない。

`--stream`は値の対応表(マッピング)と、改行が来るまでの1行分のバッファをプロセス終了まで保持し続ける。極端に長時間・大量のユニークな値が出続ける運用では、その分メモリ使用量が増えていく。

## masker profile list

登録済みプロファイルの一覧を表示する。プロファイル名・ルール数・アクティブ/お気に入りの状態・更新日時を表示する。

## masker profile use \<name\>

アクティブプロファイルを切り替える。以後`--profile`を省略した`mask`はこのプロファイルを使う。

## masker profile create \<name\> [--from-json \<file\>]

新規プロファイルを作成する。

`--from-json`を省略した場合はルール0件の空プロファイルを作成する。

`--from-json <file>`を指定した場合、そのファイルの内容(ルール定義のJSON配列)を読み込んで初期ルール入りで作成する。次のいずれかに該当する場合はエラーになり、プロファイルは作成されない(部分的に作成されることはない)。

- ファイルが存在しない、または読み込めない
- JSONとして構文が不正
- 個々のルール定義が不正(正規表現が不正、`fixed`モードで`fixed_value`未指定など)
- ルール名がファイル内で重複している

`--from-json`のJSON形式は以下の配列(1要素が1ルール)。

```json
[
  {
    "name": "ip",
    "pattern_type": "regex",
    "pattern": "\\d+\\.\\d+\\.\\d+\\.\\d+",
    "mode": "sequential",
    "prefix": "__MASK_IP_"
  }
]
```

- `pattern_type`: `"literal"` または `"regex"`
- `mode`: `"fixed"`(常に同じ値に置換。`fixed_value`が必須) または `"sequential"`(検出順に連番。`prefix`が必須)
- `enabled`: 省略可(既定`true`)
- `description`: 省略可

プロファイル名の空文字列・前後の空白は特別扱いされず、そのまま名前として作成できる。

## masker profile delete \<name\>

プロファイルを削除する。アクティブなプロファイルは削除できない(先に`profile use`で他のプロファイルに切り替える必要がある)。

## masker export [--profile \<name\>] --output \<file\>

プロファイルをパスフレーズで暗号化し、指定したファイルへ書き出す。他のマシン・他のユーザーへ持ち出す用途を想定しており、そのマシンのローカル鍵(`masker init`で生成される鍵ファイル)は使わない。

`--profile <name>`を指定すると、そのプロファイル1件(お気に入り・タグを含む)のみをエクスポートする。省略した場合は全プロファイル(お気に入り・タグを含む)とアクティブプロファイル名をまとめてエクスポートする(PC移行用)。

パスフレーズはコマンドライン引数・環境変数・標準入力のいずれからも渡せず、実行時にTTYへの直接入力のみで受け付ける(シェル履歴やプロセス一覧に残らない)。タイプミス対策として2回入力を求め、一致しない場合は何も書き出さずエラーになる。空のパスフレーズ(2回とも何も入力しない)は保護にならないため拒否される。

入力したパスフレーズは強度チェック(`zxcvbn`)を受ける。推奨レベル未達(0〜4の5段階中スコア3未満)の場合は理由を表示し「このまま続行しますか? (y/N)」と確認する。Nの場合(既定)はパスフレーズの入力からやり直す。強制的な拒否ではないため、yと答えれば弱いパスフレーズのままエクスポートできる。

出力ファイルの内容は[age](https://age-encryption.org/)形式のバイナリ(暗号化アルゴリズム: scrypt+ChaCha20-Poly1305)であり、拡張子は任意。

## masker import --input \<file\> [--yes]

`masker export`で作成したファイルからプロファイルを取り込む。ファイルの中身(単一/全体を区別する種別タグ)から自動判別するため、`--profile`に相当する引数は無い。パスフレーズはexportと同様にTTY入力のみ(確認再入力はしない)。

復号・内容の検証が失敗する場合(単一/全体を問わない)は次のいずれかが原因で、プロファイルは作成されない。

- パスフレーズが誤っている、またはファイルが破損している
- エクスポート元のマシンがこのマシンより著しく高速で、暗号化に使われたワークファクタ(scryptのコストパラメータ)がこのマシンの許容上限(2^22)を超えている場合。この場合は「パスフレーズが誤っている」とは別の専用メッセージが表示される(パスフレーズの再入力では解決しない)
- 正しく復号はできたが、中身が`masker export`で作成したデータではない、またはこのmaskerが対応していないフォーマットバージョンで作成されている(エクスポート元・インポート先のバージョンの差異を確認する必要がある)
- (全体のみ)ファイル自体に同名のプロファイルが複数含まれている(手動で編集された等、`masker export`が生成した正規のファイルでは発生しない)。この場合はリネームによる解決はせず、ファイル全体を拒否する

復号に成功した後の挙動はファイルの種別で異なる。

**単一プロファイル**: ファイル内のプロファイル名が取り込み先に既に存在する場合はエラーになり、作成されない(`profile create`の重複時と同じ扱い。リネームはしない)。

**全体(全プロファイル+設定)**: 名前が重複するプロファイルは自動的にサフィックスを付けてリネームする(例: `SIP監視用` → `SIP監視用 (インポート)`。2回目以降の衝突は`(インポート 2)`のように連番になる)。参照するタグが取り込み先に存在しなければ新規作成する(タグは名前のみの情報のため衝突しない)。書き込み前に各プロファイルがどう扱われるか(そのまま作成/リネームされる)を一覧表示し、「続行しますか? (y/N)」を1回だけ確認してから、全件を1つの操作としてまとめて書き込む(一部だけが作成された状態にはならない)。`--yes`を指定するとこの確認を省略する(cron/SSH等の非対話環境向け)。`--yes`を指定せず標準入力がTTYでない場合は、確認待ちでハングせず即座にエラーになる。ファイルに記録されたアクティブプロファイル名は、取り込み先に既にアクティブなプロファイルが設定されている場合は適用されず、未設定の場合のみ採用される(リネームされていれば、リネーム後の名前が採用される)。
